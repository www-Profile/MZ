О проекте

Личный сайт-портфолио, созданный с нуля без конструкторов и фреймворков. Главная задача — показать навыки веб-разработки в реальном проекте и дать посетителю удобный способ связаться.

Что реализовано

  • Одностраничный лендинг с четырьмя смысловыми блоками
  • Адаптивная вёрстка под ПК, планшеты и телефоны
  • Мобильное меню-бургер с выезжающей панелью
  • Интерактивный блок навыков с накопительными стикерами
  • Форма заявки с отправкой прямо в VK
  • Тёмная тема с акцентным градиентом и сетчатым фоном
  • Анимации появления, hover-эффекты, плавные переходы

Технологии

HTML5 CSS3 JavaScript Flexbox / Grid Fetch API VK API Manifest / PWA

Сложности и решения

Основная сложность — заставить сайт выглядеть одинаково хорошо на всех экранах, не используя готовых библиотек. Решил через CSS Grid для сеток и кастомные media-запросы. Отправка формы напрямую в VK потребовала режима no-cors, потому что VK API не отдаёт CORS-заголовки для браузерных запросов.

Сложности и решения

Синхронизация реального времени. При совместной тренировке несколько участников одновременно обновляют прогресс в Firestore. Возникали race conditions, когда «записанный» прогресс затирался старым. Решение — точечные обновления через пути вида participantProgress.${uid} (Firestore мержит по полям) + серверные таймстампы + идемпотентность операций.

Офлайн-режим. Firestore отдаёт кэш, но при отсутствии сети нужно было не потерять тренировки. Решение — локальная очередь pendingWorkouts с уникальными localId, синхронизация при событии online или следующем запуске.

Производительность. Каждая тренировка делала 5-10 запросов к Firestore. Решение — многоуровневый кэш с TTL и дедупликация in-flight запросов, плюс батч-запросы для профилей друзей.

Лимит Firestore 1 МБ на документ. Посты с фото превышали лимит. Решение — сжатие через Canvas с подбором размера/качества до целевого размера base64-строки.

UX длинной регистрации. 7 шагов — много отказов. Решение — плавные анимации, прогресс-полоски, возможность пропустить шаги, чёткое объяснение зачем нужны данные.

RECORD

Лендинг для спортзала в Санкт-Петербурге

О проекте

Одностраничный сайт-визитка для спортзала. Главная задача — конвертировать посетителя в звонок или запись на тренировку. Атмосфера «настоящего мужского спорта» создаётся через тёмную палитру, крупную типографику Oswald, свободные веса на фото и красные акценты.

Каждый блок ведёт к целевому действию: hero с призывом выбрать абонемент → особенности зала → галерея → прозрачные тарифы с выделенным «хитом» → прямая связь телефоном и формой.

Структура сайта

  • Sticky-шапка с логотипом, меню, телефоном и бургером для мобильных
  • Hero-секция с фоновым фото, затемнением и размытым овалом под текстом — для читаемости на любой картинке
  • Блок «Почему RECORD» — 6 карточек с иконками: веса, кардио, тренеры, фитнес для девушек, душ, время работы
  • Галерея из 6 фотографий зала с подписями и hover-эффектом «оживления цвета»
  • Тарифы — 3 карточки с выделением популярного варианта и бейджем «Хит»
  • Контакты — телефон, адрес, режим работы и встроенная Яндекс.Карта
  • Футер с копирайтом

Дизайн и визуальные приёмы

  • Тёмная палитра с красным акцентом — ассоциируется с силой и энергией
  • Плавный переход от фотографии к тёмному фону через градиент
  • Размытый овал под hero-текстом: текст читается на любом фоне без отдельной плашки
  • Фото галереи в спокойных фильтрах, при наведении становятся ярче — эффект «оживления»
  • Кастомный красный скроллбар в цвет бренда
  • Плавный скролл по якорям навигации

Адаптивность

  • Десктоп: 3 фото в галерее, 3 карточки тарифов в ряд
  • Планшет: галерея перестраивается в 2 колонки
  • Мобильные: галерея в 2 колонки, тарифы в 3 узкие колонки, блок «О нас» — 2 карточки в ряд
  • Отдельная оптимизация под очень узкие экраны — пропорциональное уменьшение шрифтов и отступов, чтобы всё уместилось без горизонтального скролла
  • На мобильных меню и телефон скрыты, логотип центрируется — фокус на контенте

Технологии

HTML5 CSS3 Grid / Flexbox Vanilla JavaScript PWA Manifest Яндекс.Карты Font Awesome Google Fonts

Сложности и решения

Читаемость текста на фоне фото. На hero-секции стоит фотография зала, а поверх — крупный заголовок. Тёмное затемнение делало фото скучным. Решение — дополнительно размытый полупрозрачный овал через filter: blur(40px) только под блоком с текстом: картинка остаётся яркой по краям, а в центре текст читается идеально.

Узкие экраны. Тарифы с 3 карточками на мобильных обычно превращаются в вертикальный список — это занимает много места. Решение — оставить их в 3 колонки, но радикально уменьшить шрифты и отступы через отдельный медиа-запрос под 380px. Пользователь сразу видит все варианты и сравнение цен.

Единая типографика. Oswald и Roboto загружаются с Google Fonts — важна скорость первой отрисовки. Подключены через preconnect и один объединённый запрос со всеми начертаниями.

О проекте

Полноценный сайт-презентация горнолыжного курорта с интерактивными элементами. Концепция — премиальный зимний отдых: холодная палитра голубого и тёмно-синего, снежная анимация, элегантная типографика Playfair Display для заголовков и Montserrat для текста.

Каждый раздел ведёт посетителя по воронке: узнать о курорте → изучить трассы → выбрать проживание → купить ски-пасс → забронировать отдых. Интерактивные карточки трасс и отелей открывают модальные окна с подробной информацией.

  • Правила безопасности — 6 карточек с иконками
  • Проживание — 4 варианта от апартаментов до VIP-резиденции с подробными модалками
  • Прокат снаряжения с ценами и брендами

Сложности и решения

Переиспользование модалок. Для трасс и проживания нужны одинаковые по структуре модалки с разными данными. Решение — вынести данные в JS-объекты и заполнять один и тот же шаблон при клике на карточку. Один HTML-блок модалки на два типа контента.

Снежная анимация без лагов. Постоянная генерация снежинок через setInterval быстро нагружает браузер. Решение — генерация только на десктопе (на мобильных отключена), ограничение количества одновременно висящих снежинок и автоматическое удаление через 13 секунд.

Параллакс без дёрганья. При движении мыши обновление background-position вызывало рывки. Решение — ограничение обновлений через проверку ширины экрана и небольшие коэффициенты смещения — эффект заметный, но не резкий.

Активный пункт меню при скролле. Нужно было определять, какой раздел сейчас в фокусе. Решение — расчёт позиции каждой секции относительно скролла и подсветка соответствующей ссылки через IntersectionObserver + scroll-listener с поправкой на высоту шапки.

О проекте

Приложение для запоминания информации через систему карточек: с одной стороны — вопрос или слово, с другой — ответ или определение. Подходит для изучения языков, терминов, столиц, формул и любых других пар «вопрос-ответ».

Полностью работает офлайн — все данные хранятся в localStorage браузера. Устанавливается на телефон как PWA и выглядит как нативное приложение.

Разделы и карточки

  • Несколько независимых разделов (колод) — например, «Английский», «Столицы мира», «Наука»
  • Создание и удаление разделов
  • Добавление, редактирование и удаление карточек в каждом разделе
  • Отметка карточек как избранных звёздочкой прямо на карточке или в списке
  • Отдельный список всех карточек раздела с возможностью быстро отредактировать или удалить
  • Счётчик карточек и избранных в каждом разделе
  • Автосохранение всего состояния в localStorage

Способы просмотра

  • Режим «колода» — по одной карточке с переворотом по клику
  • Режим «список» — все карточки раздела списком с быстрыми действиями
  • Фильтр «только избранные» — учить только отмеченные звёздочкой
  • Управление с клавиатуры: пробел — перевернуть, Escape — закрыть модалку
  • Автоматический переход на следующую карточку после просмотра ответа

Сортировка

  • По порядку — карточки идут как добавлены
  • Рандом — перемешивание для лучшего запоминания
  • С конца — обратный порядок
  • Избранные вперёд — сначала карточки со звёздочкой
  • Опция «перемешивать при старте раздела» — каждый заход в раздел начинается со случайного порядка

Сложности и решения

Синхронизация отображения с фильтром. Когда включён фильтр «только избранные», индекс карточки в отфильтрованном списке не совпадает с её индексом в полном массиве раздела. Решение — отдельный массив viewIndices, где хранятся реальные индексы видимых карточек. Все операции (переворот, отметка звёздочкой, переход вперёд) работают через этот массив, а изменения применяются к настоящей карточке в исходном массиве.

Управление порядком карточек без изменения исходного массива. Рандом и сортировка не должны ломать физический порядок карточек в разделе — иначе при выключении сортировки всё останется перепутанным. Решение — массив viewOrder с индексами: сортируется только он, а настоящий массив карточек остаётся нетронутым.

Обновление данных в момент переворота. Обновлять текст сразу при клике нельзя — пользователь увидит, как на ещё видимой стороне мелькает значение следующей карточки. Решение — обновлять данные на скрытой стороне строго после завершения анимации. Ждём окончания переворота, и только тогда подставляем новое слово на невидимой лицевой стороне (или новое определение на скрытой задней). К моменту, когда сторона снова станет видимой, там уже нужный текст — без «мельканий» чужих значений.

Сложности и решения

Несколько экземпляров одного виджета. Виджеты заметок и рисовалок можно добавлять многократно, но у каждого должны быть свои данные. Решение — каждому экземпляру при создании присваивается уникальный ID на основе времени и случайной строки, а данные хранятся по ключу с этим ID. Клонирование виджета при создании идёт через cloneNode с последующей заменой ID и очисткой данных.

Drag-and-drop с индикатором. При перетаскивании виджета между существующими блоками нужно показать, куда именно он попадёт. Решение — отдельный элемент-индикатор, который позиционируется по координатам курсора относительно середин виджетов и удаляется после сброса. Порядок сохраняется в localStorage.

Рисование на canvas. Стандартные события mouse не учитывают, что canvas может быть меньше своего CSS-размера. Решение — пересчёт координат через getBoundingClientRect() и сохранение истории изменений через getImageData с поддержкой отмены и повтора.

Безопасность заметок. Пользователь может ввести в заметку HTML-тег, и он выполнится. Решение — экранирование через временный DOM-элемент с textContent перед вставкой. Так тег отображается как текст, но не исполняется.

Восстановление виджетов после перезагрузки. Виджеты хранятся в двух местах: HTML-шаблон и список созданных пользователем. При загрузке статичные удаляются и создаются заново из сохранённых данных — это позволяет гибко менять HTML без потери состояния пользователя.
